## SECTION 01 · 실무 판단 4가지 기준 (4:00~11:00, 7분)

[스크롤]

먼저 중요한 말부터 할게요.

**"파레토 순위는 출발점이고, 실제 조치 순서는 네 가지 기준으로 정합니다."**

[잠깐]

건수 1위가 항상 조치 1순위는 아니에요. 빈도, 영향도, 변화율, 조치 난이도를 분리해서 봐야 회의에서 실행 가능한 판단이 나와요.

네 가지를 하나씩 볼게요.

[잠깐]

**첫째 — 빈도.** "얼마나 많이 발생했는가?"

유형별 건수, 점유율, 누적 기여율로 전체 손실의 큰 덩어리를 찾아요. 가장 기본 기준이에요.

**둘째 — 영향도.** "수율과 비용을 얼마나 깎는가?"

심각도, 패널 폐기 여부, 재작업 비용을 반영해요. 건수가 적어도 폐기율이 높으면 손실 기준 순위가 올라갈 수 있어요.

**셋째 — 변화율.** "최근에 얼마나 빠르게 커지는가?"

최근 4주와 기준 4주를 비교해요. 누적 상위 불량과 급증 불량을 따로 봐야 해요.

**넷째 — 조치 난이도.** "지금 바로 확인할 수 있는가?"

설비 정지나 장기 실험이 필요한 항목과 즉시 점검 가능한 항목을 나눠요.

[잠깐]

이 네 가지를 정리하면 판단 질문이 나와요.

**"이 불량이 1위입니다"에서 멈추지 말고 — "왜 이 불량을 먼저 봐야 하는지"를 수치와 확인 데이터로 설명할 수 있어야 합니다.**

이게 회의에서 실행 가능한 조치 순서를 끌어내는 핵심이에요.

## SECTION 02 · 파레토 개념 + 계산식 (11:00~19:00, 8분)

[스크롤]

파레토 분석이 뭔지 정확히 짚어볼게요.

**"파레토는 상위 몇 개 불량이 전체 손실의 대부분을 만드는가를 확인하는 도구입니다."**

공정 현장에서는 모든 불량을 동시에 해결할 수 없어요. 파레토 분석은 제한된 시간과 인력을 가장 큰 손실 요인에 먼저 배치하기 위한 우선순위 도구예요.

[잠깐]

세 가지 분석 기준이 있어요.

**개수 기준** — 가장 많이 발생한 불량이에요. 검사 로그에서 유형별 빈도를 집계해요. 단순하지만 현장 회의의 출발점으로 좋아요.

**영향 기준** — 수율을 가장 많이 깎는 불량이에요. 불량 개수에 심각도, 패널 폐기 여부, 재작업 비용을 곱해서 실제 손실 기여도를 봐요.

**변화 기준** — 최근 급격히 커지는 불량이에요. 누적 상위가 아니어도 최근 2~4주 상승률이 크면 선제 조치 대상이 돼요.

[잠깐]

[스크롤]

계산식이에요.

**불량 점유율** = 유형별 불량 수 ÷ 전체 불량 수 × 100

**누적 기여율** = 상위 유형부터 점유율을 순서대로 더한 값

**트렌드 변화율** = 최근 기간 평균 ÷ 기준 기간 평균 − 1

[잠깐]

이 세 가지 계산식이 파레토 차트, 주차별 트렌드, 최근 급증 탐지의 기초예요.

[잠깐]

**흔한 오해** 하나예요. **"상위 80%만 보면 나머지는 무시해도 된다"는 뜻이 아니에요.** 하위 항목 안에도 치명도가 높은 불량이 있을 수 있어요. 파레토 순위는 조치 순서의 출발점이며, 영향도와 최근 변화율을 반드시 함께 봐야 해요.

## SECTION 03 · 실무 데이터 + 3가지 시나리오 (19:00~29:00, 10분)

[스크롤]

실무 데이터 예시로 넘어갈게요.

**"같은 불량 데이터도 파레토, 트렌드, 액션 매트릭스로 보면 판단이 달라집니다."**

가상의 디스플레이 패널 검사 로그예요.

| 불량 유형 | 건수 | 점유율 | 최근 변화 | 1차 조치 방향 |
|---|---|---|---|---|
| Particle | 342 | 35.7% | **+44%** | 세정/이송 구간 이물원 추적 |
| Scratch | 238 | 24.8% | +8% | 이송 롤러, 카세트 접촉부 점검 |
| CD Drift | 168 | 17.5% | **+31%** | 노광/현상 조건과 계측 위치 재확인 |
| Mura | 96 | 10.0% | -5% | 증착 균일도 로그와 비교 |
| Open | 71 | 7.4% | +2% | 패턴 끊김 위치를 공정맵과 매칭 |
| Etch Residue | 43 | 4.5% | -12% | 식각 후 세정 recipe 유지 관찰 |

[잠깐]

이 표에서 세 가지 시나리오 카드로 판단 방법을 설명할게요.

[스크롤]

**시나리오 1 — Particle, 누적 1위 + 급증.**

건수 342건, 점유율 35.7%, 최근 +44%예요. 누적 최다이면서 증가율도 높아요. Line, process, 좌표 분포를 분리해서 세정/이송 구간의 원인 범위를 좁혀야 해요.

이건 분명한 1순위예요. 건수도 많고, 빠르게 커지고 있으니까요.

[잠깐]

**시나리오 2 — CD Drift, 누적 3위 + 급증.**

건수는 3위예요. 점유율이 17.5%고, 최근 +31%예요. 건수 순위만 보면 3위라 Scratch 다음으로 넘어갈 수 있어요.

그런데 변화율이 문제예요. +31%면 지금 빠르게 커지고 있는 불량이에요. 계측 calibration, 노광 dose/focus, 현상 조건, recipe 변경 이력을 긴급 확인해야 해요.

건수 3위지만 **급증 불량이라는 이유로 조치 순서가 올라가요.** 이게 파레토만 보면 놓치는 포인트예요.

[잠깐]

**시나리오 3 — Open, 저빈도 + 고영향 가능.**

건수는 71건으로 5위예요. 점유율도 7.4%예요. 파레토 순위로는 하위예요.

그런데 Open 불량은 패턴이 끊긴 거잖아요. 패널을 폐기해야 할 수 있어요. 폐기율이 높으면 — 건수는 71건이어도 실제 손실은 훨씬 클 수 있어요.

이런 경우 severity를 반영한 **가중 파레토**로 다시 확인해야 해요. 단순 건수 파레토와 손실 금액 파레토를 같이 봐야 하는 이유예요.

[잠깐]

세 시나리오를 정리하면 — Particle은 건수 1위에 급증이라 분명한 우선 조치, CD Drift는 건수 3위지만 급증이라 조치 순서 올라옴, Open은 건수 적지만 폐기율 확인 필요. 이렇게 세 유형이 다 달라요.

[스크롤]

AI 프롬프트 3가지예요. 각 차트를 직접 만들 때 쓰는 지시문이에요.

**파레토 차트 생성 프롬프트**

```
내가 제공한 defect_log.csv 데이터를 기반으로 파레토 차트를 그려줘.
1. X축은 '불량 유형', Y축 좌측은 '발생 건수' 막대그래프,
   Y축 우측은 '누적 점유율(%)' 꺾은선으로 이중 축 설정.
2. 누적 점유율이 80%가 되는 지점에 붉은색 수평 점선을 그어 줘.
3. 80% 이내에 속하는 불량 유형들은 '핵심 관리 대상'으로
   막대 색상을 진하게 표시해 줘.
```

**트렌드 차트 생성 프롬프트**

```
주차별 주요 불량의 발생 건수 추이를 꺾은선 차트로 그려줘.
1. 전체 불량이 아닌 누적 상위 5개 불량 유형만 필터링해서 보여줄 것.
2. 각 선의 끝(가장 최근 주차)에 불량 유형 라벨과 건수를 표기.
   범례 최소화.
3. 4주 전 대비 증가율이 20% 이상인 불량은
   꺾은선을 붉은색 굵은 선으로 강조해 줘.
```

**액션 매트릭스 생성 프롬프트**

```
불량 유형들을 4분면 액션 매트릭스에 배치해 줘.
1. X축은 '조치 난이도 및 예상 소요 시간',
   Y축은 '수율 영향도 및 손실 비용'.
2. 점의 크기는 '발생 건수'에 비례하게 설정 (버블 차트).
3. 좌측 상단 2사분면 (영향도 높고 난이도 낮음)의 배경을
   옅은 녹색으로 칠하고 'Quick Wins 우선 조치' 라벨을 달아 줘.
```

## SECTION 04 · Bump Chart — 순위 역전 포착 (29:00~36:00, 7분)

[스크롤]

심화 시각화예요. **Bump Chart, 불량 순위 변동 차트**예요.

**"순위 역전 현상을 포착하면, 새로운 고질 불량을 초기에 막을 수 있습니다."**

[잠깐]

단순 파레토 차트는 누적 결과를 보여주지만 '최근 치고 올라오는 불량'을 놓치기 쉬워요. 주차별 순위 변동 차트를 활용하면 항상 1등인 불량과 새롭게 급상승하는 불량을 직관적으로 구분할 수 있어요.

[잠깐]

[스크롤]

화면에 Bump Chart가 보이시죠? 4가지 불량의 Week 1부터 Week 4까지 순위 변동이에요.

- **Particle** (파란선) — 1위, 1위, 1위, **2위**. Week 4에 2위로 내려갔어요.
- **CD Drift** (노란선) — 4위, 3위, 2위, **1위**. 4주 만에 4위에서 1위로 급상승했어요.
- **Scratch** (초록선) — 2위, 2위, 4위, 4위. 오히려 하락하고 있어요.
- **Mura** (보라선) — 3위, 4위, 3위, 3위. 3위권에서 유지 중이에요.

[잠깐]

차트 아래 요약이에요. **"CD Drift가 4주 만에 4위에서 1위로 급상승하며 최우선 조치 대상으로 부상함."**

파레토 차트만 봤으면 Particle이 1위라서 거기만 집중했을 거예요. Bump Chart로 보면 CD Drift가 지금 폭발적으로 올라오고 있다는 게 보여요.

[잠깐]

순위 패턴이 세 가지 의미예요.

**순위 유지 (Horizontal) — 고질적 불량 요인.** 항상 상위권을 유지하는 불량은 근본적인 공정 개선이나 설비 개조가 필요한 장기 과제예요.

**순위 상승 (Upward) — 신규 돌발성 요인.** 갑자기 급상승하는 불량은 최근 변경된 작업자, 자재, 파츠 수명 등을 즉각 확인해야 해요.

**순위 하락 (Downward) — 개선 효과 검증.** 최근 진행한 개선 대책이 실제로 효과가 있었는지 검증하는 지표예요.

[잠깐]

Bump Chart 생성 프롬프트예요.

```
내가 제공한 defect_log.csv 데이터로 불량 순위 변동 차트를 그려줘.
1. X축은 '주차(Week)', 최근 4주치 데이터를 반영할 것.
2. Y축은 '불량 발생 건수 순위 1위~5위'로
   뒤집어서 (1위가 맨 위에 오도록) 표시할 것.
3. 불량 유형별로 선 색상을 다르게 지정하고,
   각 데이터 포인트에 해당 주차의 순위를 텍스트로 적어줄 것.
4. 순위가 2계단 이상 상승한 불량 유형이 있다면
   차트 옆에 강조해서 요약해 줘.
```

## SECTION 05 · AI 파이프라인 + 작업지시서 (36:00~46:00, 10분)

[스크롤]

이제 핵심 파이프라인이에요.

**"AI에게 맡길 일은 '차트 그리기'가 아니라 '차트에서 조치안까지 이어가기'입니다."**

흐름이에요 — Raw defect log → Clean & group → Pareto → Trend → Action memo. 이 흐름 전체를 AI가 이어가게 만드는 게 목표예요.

[잠깐]

나쁜 지시문과 좋은 지시문을 비교할게요.

**나쁜 지시문** — *"defect_log.csv 분석해서 파레토 차트 그려줘."*

컬럼, 기간, 결측 처리, 중복 기준, 산출물 형식이 없어서 AI가 임의로 가정해요.

**좋은 지시문** — *"최근 4주와 이전 4주 평균을 비교하고, 결측 defect_type, 잘못된 date, 중복 panel_id를 경고하며, 상위 80%와 급증 Top 3를 분리해 보고서 문장으로 작성해라."*

분석 기준, 검증 기준, 결과 형식이 명확해서 회의 자료로 옮기기 쉬워요.

[잠깐]

[스크롤]

AI 지시서의 **5가지 블록**이에요.

**역할** — *"너는 디스플레이 제조 데이터 분석을 돕는 공정 엔지니어링 분석가다."*

**입력 데이터** — *"컬럼: date, line, process, panel_id, defect_type, x, y, severity, lot_id. 결측치와 이상값은 따로 표시해라."*

**분석 작업** — *"불량 유형별 파레토, 주차별 트렌드, 라인별 편차, 최근 4주 급증 유형을 계산하고 표와 차트로 요약해라."*

**검증 기준** — *"총 불량 수 합계가 원본 행 수와 맞는지 확인하고, 상위 80%를 만드는 유형을 별도로 표시해라."*

**산출물** — *"우선 조치 3개, 원인 가설, 필요한 추가 데이터, 다음 실험 계획을 엔지니어 보고서 문장으로 작성해라."*

[잠깐]

이 구조 기억하세요. **역할 → 입력 데이터 → 분석 작업 → 검증 기준 → 산출물.** 다섯 블록이 다 있어야 AI가 임의 가정 없이 작업해요.

[스크롤]

실습 작업지시서예요. 같이 읽어볼게요.

```
내가 가진 defect_log.csv를 분석하는 웹 도구를 만들어줘.

필수 기능:
1. CSV 업로드 후 defect_type, date, line, process 기준으로 집계

6. 우선 조치 후보 3개를
   '불량명 / 근거 / 확인할 데이터 / 다음 실험' 형식으로 출력
```

## SECTION 06 · 검증 체크리스트 + 마무리 (46:00~50:00, 6분)

[스크롤]

마지막이에요.

파레토 차트는 강력하지만 기준을 잘못 잡으면 엉뚱한 조치로 이어져요.

**3.** 검사일, 공정 투입일, lot 종료일 중 어떤 날짜 기준으로 트렌드를 집계했는가?

**4.** 개수 기준과 수율 영향도 기준을 혼동하지 않았는가?

**5.** 최근 급증한 불량과 누적 상위 불량을 따로 해석했는가?

**6.** AI가 만든 원인 가설을 설비 로그, recipe 변경 이력, LOT 이력으로 검증했는가?
