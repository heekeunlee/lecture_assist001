예상 시간: 1:30 ~ 6:00 (4분 30초)

↓ 스크롤

섹션 01 — 오프닝 및 학습목표예요.

화면에 이런 h2가 보이시죠?

"오늘 여러분은 '코딩 문법'이 아니라 'AI 작업지시서'로 반도체, 디스플레이, 2차 전지 등 엔지니어의 업무를 이해할 수 있습니다"

이 한 줄이 오늘 강의 전체의 핵심이에요. ⏸ 잠깐

이 강의는 개발자가 되기 위한 문법 수업이 아니에요. "무엇을 만들지, 어떤 데이터를 쓸지, 어떤 기준으로 판단할지"를 AI에게 정확히 설명하는 법을 배우는 첫 시간이에요.

↓ 스크롤

학습목표 카드 세 개가 보이시죠? 같이 보겠습니다.

학습목표 1 — 바이브 코딩의 뜻을 한 문장으로 설명.

코드를 직접 치는 방식이 아니라, 원하는 결과를 말로 설명하면 AI가 코드를 대신 만들어주는 방식. 이게 바이브 코딩이에요.

학습목표 2 — 좋은 작업지시서의 요소 구분.

화면에 보이는 태그들 — 문제, 데이터, 기준, 산출물, 검증. 이 다섯 가지가 다 있어야 AI가 현장 기준에 맞는 결과를 만들 수 있어요.

학습목표 3 — 현장 사례와 연결.

수율, AOI, 설비 센서 같은 반복 업무를 AI 작업지시서로 바꾸는 흐름을 설명할 수 있게 돼요.

↓ 스크롤

아래에 40분 강의 타임라인이 있어요. 목표 확인 3분, 개념·비유 7분, 실무 사례 8분, 지시문·실습 17분, 검증·정리 5분. 이 흐름으로 진행할게요.

SECTION 02 · 바이브 코딩이란?

예상 시간: 6:00 ~ 15:00 (9분)

↓ 스크롤

섹션 02 — 바이브 코딩이란?

큰 제목을 보면요:

"바이브 코딩은 '코드를 치는 일'보다 'AI가 일할 수 있게 주문서를 쓰는 일'에 가깝습니다"

⏸ 잠깐

요리사 비유로 시작할게요.

요리사가 칼질과 조리를 맡더라도 — 주문서가 부정확하면 원하는 음식이 나오지 않아요. 바이브 코딩도 마찬가지예요.

사람은 문제, 데이터, 판단 기준, 원하는 결과물을 설명하고, AI는 코드, 차트, 대시보드, 보고서 초안을 만들어요.

↓ 스크롤

화면에 파란 박스가 하나 있어요. "한 문장 정의" 박스예요. 같이 읽어볼게요.

"바이브 코딩은 코드를 직접 짜는 것이 아니라, 내가 만들고 싶은 결과를 말로 설명하면 AI가 코드를 대신 만들어주는 방식입니다."

⏸ 잠깐 이게 전부예요. 이 한 문장이 바이브 코딩의 정의예요.

↓ 스크롤

아래에 세 칸짜리 비교 박스가 있어요.

기존 코딩 — 사람이 문법을 외우고 코드를 직접 작성.

바이브 코딩 — 사람이 작업지시서를 쓰고 AI가 초안을 구현.

사람의 역할 — 문제 정의, 기준 제시, 결과 검증.

⏸ 잠깐

여기서 중요한 게 하나 있어요. 바이브 코딩에서도 사람의 역할이 사라지는 게 아니에요. 오히려 더 중요한 일을 해요. 문제를 정의하고, 기준을 제시하고, 결과가 맞는지 검증하는 — 그게 엔지니어의 역할이에요.

↓ 스크롤

역할 분리 흐름도가 있어요.

엔지니어 → 문제·데이터·기준 정의 → AI → 코드·차트·보고서 초안 생성 → 엔지니어 → 현장 기준으로 검증·수정 지시

이 세 단계가 바이브 코딩의 전체 흐름이에요.

↓ 스크롤

전통 방식과 바이브 코딩을 이미지로 비교한 카드 두 개가 있어요.

왼쪽 — Traditional (Process Focused) — 구현 과정과 문법을 직접 관리합니다. 로직을 한 줄씩 짜고, 오타와 싸우는 과정에 에너지를 씁니다.

오른쪽 — Vibe Coding (Target Focused) — 해결 목표를 정의하면 AI가 도구를 완성합니다. "어떤 데이터를 분석하고 어떤 결과를 얻을지"라는 목표를 먼저 세워요.

↓ 스크롤

아래 노란 박스, "혁신의 핵심" 이에요.

"코딩 실력의 출발점이 '문법 암기'에서 '문제 정의 능력'으로 이동합니다. 그래서 첨단 공정기술 엔지니어에게 필요한 것은 개발자가 되는 것이 아니라, AI가 일할 수 있을 만큼 정확하게 공정 문제를 설명하는 능력입니다."

예상 시간: 15:00 ~ 21:00 (6분)

↓ 스크롤

섹션 03 — 핵심 비유예요. 제목을 보면:

"바이브 코딩은 엔진 조립이 아니라 목적지를 말하는 일입니다"

인용구 박스가 있어요. 같이 읽어볼게요.

"자동차 운전을 할 때 엔진 오일의 점도나 피스톤의 회전 속도를 일일이 계산하며 타시나요?"

⏸ 잠깐

당연히 아니죠. 운전자는 엔진을 직접 조립하지 않아도 목적지, 속도, 안전 기준을 정합니다. 바이브 코딩에서도 구현은 AI가 돕고, 엔지니어는 문제 정의와 검증 기준을 책임집니다.

↓ 스크롤

화면에 카드 세 개가 가로로 이어진 네비게이션 비주얼이 있어요.

목적지 → Array 수율 하락 원인 후보

조건 → 최근 7일, 3% 이상 하락

도착 결과 → 차트 + TOP5 + 확인 질문

⏸ 잠깐

이게 바이브 코딩의 구조예요. 목적지와 조건을 말하면 — AI가 결과를 만들어줘요.

↓ 스크롤

만화 4컷이 있어요.

복잡한 엔진 원리 몰라도 → 그냥 시동 걸고 출발! → 목적지만 정하세요 → 즐거운 여행 성공!

⏸ 잠깐

그리고 큰 글씨로 이런 문장이 있어요:

"복잡한 구현(코딩)은 AI가, 최종 목적지(의도) 결정은 엔지니어가 합니다."

↓ 스크롤

노란 박스, "꼭 기억하세요!" 에요.

"여러분, 삼성이든 SK하이닉스든 현장에서 원하는 엔지니어는 '코드를 잘 치는 사람'이 아닙니다. '데이터를 보고 어떤 로직이 필요한지 설계할 수 있는 사람'입니다."

SECTION 04 · 전통 코딩 vs 바이브 코딩

예상 시간: 21:00 ~ 27:00 (6분)

↓ 스크롤

섹션 04 — 전통 코딩 vs 바이브 코딩이에요.

"'과정'을 하나씩 짜는 사람 vs '목표'를 명확히 정의하는 사람"

서브 설명을 보면요 — 코알못에게는 "기술이 다르다"보다 "생각 순서가 다르다"가 더 중요하다고 해요.

↓ 스크롤

두 개의 칼럼이 나란히 있어요.

왼쪽 Traditional — 구현 과정을 하나씩 조립.

화면에 코드 에디터 비주얼이 있어요. import pandas, 코드 라인들, 그리고 빨간 에러 메시지가 보여요. `Error: ModuleNotFoundError: No module named 'matplotlib'`. ⏸ 잠깐

이게 기존 코딩의 현실이에요. 에러 하나에 멈춰서 모듈 설치하고, 다시 에러 나고 — 현장 문제 풀기 전에 코드 문제에 발목 잡히는 거예요.

오른쪽 Vibe Coding — 최종 해결 목표를 정의.

여기는 Antigravity라는 AI 분석 도구 비주얼이 있어요. 채팅창에 이렇게 입력해요: "1000개의 공정 데이터 중에서 이상점이 발생한 부분을 진단하고 그것을 시각화해줘." 그러면 가우시안 밀도 분포, 박스플롯, 진단 보고서가 나와요.

⏸ 잠깐

같은 목표인데 — 한쪽은 에러와 싸우고, 한쪽은 결과를 보고 있어요.

↓ 스크롤

아래 비교표가 있어요. 세 줄이에요.

입력 — 전통: 문법, 라이브러리, 에러 메시지 / 바이브: 문제, 데이터, 기준, 결과물

초점 — 전통: 어떻게 코드를 만들까 / 바이브: 무엇을 해결할까

결과 — 전통: 직접 작성한 코드와 수정 흔적 / 바이브: 대시보드, 차트, 보고서 초안

SECTION 05 · 왜 중요한가?

예상 시간: 27:00 ~ 32:00 (5분)

↓ 스크롤

섹션 05 — 왜 중요한가?

"왜 첨단 공정기술 엔지니어에게 중요한가?"

AI는 공정 지식을 대신하지 않아요. 대신 반복되는 데이터 정리, 초안 작성, 이상 구간 탐색을 빠르게 처리해서 — 엔지니어가 원인 판단과 의사결정에 더 많은 시간을 쓰게 만들어요.

↓ 스크롤

카드 세 개가 있어요. Before와 After After를 비교해볼게요.

반복 보고서 — Before: Excel 파일을 열고 필터, 피벗, 캡처를 수작업으로 반복. After: 데이터 범위와 기준을 지시하면 표, 그래프, 요약 초안을 자동 생성.

이상 감지 — Before: 관리 한계 초과 구간을 사람이 직접 찾고 원인을 메모. After: OOC 시점, 관련 센서, 확인 질문을 한 화면에서 검토.

회의 준비 — Before: 불량 이미지와 수율 로그를 따로 모아 발표 자료를 구성. After: 대표 이미지, 우선순위, 조치 후보가 포함된 리뷰 자료 초안 생성.

⏸ 잠깐

이게 바이브 코딩이 주는 실질적 가치예요.

↓ 스크롤

회색 박스 — Target Point 예요.

"기업은 단순 문법 암기자가 아니라, AI를 활용해 공정 데이터 분석·보고서·이상감지를 빠르게 자동화하는 첨단 공정기술 엔지니어를 원합니다."

그리고 아래에 AI가 만들어주는 샘플 대시보드가 있어요 — 수율 추이 그래프와 1-page 보고서 예시예요. 이상 구간, 원인 후보, 확인 질문이 담겨 있어요.

SECTION 06 · 첨단 공정기술 사례

예상 시간: 32:00 ~ 44:00 (12분)

↓ 스크롤

섹션 06 — 첨단 공정기술 사례예요.

"이 강의는 일반 코딩 수업이 아니라, 반도체·디스플레이·이차전지 등 첨단 공정기술 엔지니어의 업무 자동화 수업입니다"

바이브 코딩의 출발점은 문법이 아니라 현장 문제예요. 수율, AOI, 센서 로그처럼 이미 여러분이 알고 있는 업무 언어를 AI가 실행 가능한 지시로 바꾸는 것이 핵심이에요.

↓ 스크롤

시나리오 카드 세 개가 있어요. 빠르게 읽어볼게요.

수율 로그 자동 요약 — Before: 라인별 Excel 파일을 하나씩 열어 수율 하락 구간을 눈으로 찾음. 의도 지시문: "최근 7일간 라인/공정/모델별 수율을 비교하고 전일 대비 3% 이상 하락한 항목만 빨간색으로 표시해줘." 결과: 수율 이상 구간 TOP5와 원인 후보 요약.

AOI 불량 이미지 분류 — Before: 이미지 폴더를 넘기며 Scratch, Particle, Mura 여부를 수작업 기록. 의도 지시문: "AOI 이미지 샘플을 불량 유형별로 분류하고, 대표 이미지를 포함한 리뷰용 대시보드를 만들어줘." 결과: 불량 유형별 갤러리와 검토 우선순위.

설비 센서 OOC 감지 — Before: 온도/압력/유량 로그에서 관리 한계 초과 여부를 수동 필터링. 의도 지시문: "설비 센서 데이터에 이동평균과 UCL/LCL을 적용해서 OOC 발생 시점과 전조 패턴을 표시해줘." 결과: 관리도 기반 알림 화면과 조치 메모.

↓ 스크롤

자, 이제 각 사례를 좀 더 자세히 볼게요. Case 01 — 수율 로그 자동 요약이에요.

화면에 Before/Prompt/After 세 단계가 세로로 나와 있어요.
