## SECTION 01 · 오프닝 및 학습목표
**예상 시간: 0:00 ~ 4:00 (4분)**

안녕하세요! 드디어 마지막 10강이에요!

9강에서 E-472 알람에 대한 **1차 조치안을 5분 안에 만들었어요.** 매뉴얼 근거가 있는 우선순위 표 한 장. 이제 이걸 매주 팀 전체에 공유하려면 어떻게 해야 할까요?

보고서가 필요해요. 엑셀 열고, 차트 캡처하고, 문장 쓰고, 숫자 재확인하고 — 지금은 그 과정에 **480분**이 걸려요. 10강에서는 그걸 **15분**으로 줄여요.

오늘 강의 제목이에요. **"데이터 기반 주간/월간 보고서 자동 생성."**

1강부터 9강까지 만든 모든 분석 결과가 — 오늘 하나의 보고서 흐름으로 묶여요.

[잠깐]

오늘의 목표가 딱 한 줄이에요.

**"오늘의 목표는 분석을 더 많이 하는 것이 아니라, 이미 만든 분석을 매주 반복 가능한 보고서 시스템으로 바꾸는 것입니다."**

[잠깐]

앞 강의에서 배운 데이터 병합, 정제, 시각화, 기술 문서 요약은 각각 좋은 도구예요. 10강에서는 이 도구들이 흩어진 결과물로 끝나지 않도록 — **수율 회의와 월간 리뷰에 바로 제출할 수 있는 보고서 흐름으로 묶어요.**

[스크롤]

오늘 학습목표 세 가지예요.

**학습목표 1 — 분석 결과를 보고서 언어로 바꾸기.**
수율, 불량, 설비 상태, 문서 요약 결과를 그대로 붙여 넣지 않고 **의사결정자가 읽는 문장과 표로 재구성**해요.

**학습목표 2 — Markdown/HTML 보고서 자동화 구조 이해.**
입력 데이터, 계산 지표, 시각화, 해석 문장, 액션 아이템이 **어떤 순서로 조립되는지 파이프라인으로** 이해해요.

**학습목표 3 — AI 작업지시서로 주간 보고서 만들기.**
AI에게 맡길 계산, 사람이 검토할 근거, **최종 배포 전 체크리스트를 분리**해 반복 보고 업무를 자동화해요.

[스크롤]

오늘 강의 흐름이에요.

**4분** 1~9강 연결 → **8분** 보고서 구조 → **10분** 데이터 상자 설계 → **13분** AI 지시서 실습 → **5분** 검증/배포 기준. 총 40분이에요.

## SECTION 02 · 1~9강 흐름과 10강의 위치

[스크롤]

**"10강은 별도 기능을 하나 더 배우는 시간이 아니라, 지금까지 만든 기능을 보고 체계로 연결하는 전환점입니다."**

1강부터 9강까지의 흐름이에요.

**01~02강** — AI에게 정확히 지시하기. 결과: 역할, 입력, 산출물, 검증 기준을 갖춘 프롬프트.

**03~04강** — MES/설비 데이터 다루기. 결과: 병합, 요약, 결측/이상치 정제 흐름.

**05~08강** — 공정 상태를 그림으로 보기. 결과: 히트맵, 관리도, 산점도, 파레토/트렌드.

**09강** — 기술 문서에서 근거 찾기. 결과: 에러 코드, 매뉴얼 조치, 주의사항 요약.

**10강** — 분석 결과를 보고서로 조립하기. 결과: 주간/월간 보고서 자동 생성기.

[잠깐]

학습 파이프라인이에요.

AI 브리핑(01~02강) → 데이터 전처리(03~04강) → 시각화 도출(05~08강) → 근거 데이터 확보(09강) → **보고서 생성(10강, Markdown+HTML).**

최종 산출물은 — **KPI 요약, 명확한 분석 근거, 조치 계획이 모두 포함된 실무용 주간/월간 엔지니어링 보고서**예요.

## SECTION 04 · 보고서 템플릿 설계
**예상 시간: 18:00 ~ 22:00 (4분)**

[스크롤]

**"Markdown 보고서는 작성하기 쉽고, HTML 보고서는 공유하기 쉽습니다. 두 형식을 같은 뼈대에서 생성하도록 설계합니다."**

자동 보고서는 매번 새로 쓰는 문서가 아니라 **빈칸을 채우는 템플릿**이에요. 보고서의 고정 섹션을 먼저 설계하고, 각 섹션에 어떤 데이터와 문장이 들어갈지 연결해요.

[스크롤]

보고서의 4개 섹션이에요.

**1 — Executive Summary.**
이번 주 가장 중요한 변화 3가지를 먼저 제시해요. 숫자, 원인 후보, 필요한 의사결정을 **한 문단으로 압축**해요.

**2 — KPI Snapshot.**
수율, 불량률, OOC 횟수, 재작업률처럼 **매주 반복되는 지표를 같은 위치에 고정**해 비교 가능하게 만들어요.

**3 — Root Cause Evidence.**
파레토, 트렌드, 산점도, 매뉴얼 근거를 묶어 **왜 그런 판단을 했는지 추적 가능한 증거로** 남겨요.

**4 — Action Items.**
누가, 언제까지, 어떤 데이터를 추가 확인할지 명시해요. **보고서는 결론보다 다음 행동이 중요해요.**

[스크롤]

입력-출력 구조예요.

입력 데이터(CSV + 수동 메모) → 보고서 엔진(지표 + 차트 + LLM 텍스트) → **Markdown 리뷰용 초안 + HTML 팀 공유용** 두 가지 형식이 동시에 나와요.

필수 구성 요소 — Summary, KPI Snapshot, Evidence Charts, Action Items.
검증 규칙 — 출처 없는 숫자 금지, 단정보다 가설 형태, 담당자 및 기한 명시.
최종 산출물 요건 — **3분 내 읽기 가능, 회의 자료로 즉시 활용, 추적 가능한 다음 단계.**

## SECTION 08 · 실패 사례와 검증
**예상 시간: 33:00 ~ 36:00 (3분)**

[스크롤]

**"실전에서는 잘 만든 초안보다 잘못된 초안을 빨리 찾아내는 능력이 더 중요합니다."**

자동 보고는 편하지만 검증 기준이 없으면 오류도 빠르게 퍼져요. 가장 흔한 실패 유형 세 가지예요.

**숫자 틀림.**
Bad: 전주 대비가 아니라 전월 대비로 계산됨.
Fix: **비교 기준을 프롬프트와 코드에 동시에 고정.**

**과한 확정.**
Bad: 원인을 단정적으로 쓰고 확인 근거를 생략.
Fix: **가설과 확인 필요 항목을 분리해 서술.**

**근거 누락.**
Bad: 요약은 길지만 어느 표에서 왔는지 알 수 없음.
Fix: **문장마다 출처 지표를 붙이는 규칙 추가.**

[잠깐]

검증 규칙이에요. **계산 기준, 비교 기간, 단위, 담당자, 출처를 보고서 초안 생성 직전에 다시 명시해요.** 이 규칙 하나만 제대로 넣어도 실무 품질이 크게 올라가요.

## SECTION 09 · 실습 — AI 작업지시서 만들기
**예상 시간: 36:00 ~ 38:00 (2분)**

[스크롤]

실습 파트예요.

**"실습의 핵심은 '보고서를 만들어줘'가 아니라 입력, 계산, 시각화, 서술, 검증을 분리해서 지시하는 것입니다."**

5단계 실습 흐름이에요.

**입력** — CSV 3개: lot_summary, defect_log, equipment_alarm.

**계산** — 전주 대비 변화율, Top 3 불량, OOC 설비, 위험 등급.

**시각화** — 파레토, 수율 추이, 설비별 알람 막대, 원인 후보 표.

**서술** — 요약 문장, 원인 가설, 현장 확인 요청, 다음 주 계획.
