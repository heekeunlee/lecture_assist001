그런데 그때 한 가지를 전제하고 넘어갔어요. **데이터가 깨끗하다는 전제요.**

실제 현장은 어떨까요? 센서 로그를 열어보면 NaN이 곳곳에 박혀 있고, 갑자기 214.5°C 같은 말도 안 되는 값이 찍혀 있고, 정상 범위 안이긴 한데 위아래로 미세하게 떨리는 노이즈가 섞여 있어요.

이 오염된 데이터를 그냥 AI에게 넘기면 어떻게 될까요? AI는 그 이상치를 "공정 이상"으로 읽고 가짜 알람을 내보내요. 수율 예측 모델도 R²가 0.62밖에 안 나와요. 현장에서 쓸 수 없는 수준이에요.

4강의 핵심 질문은 이거예요. **"AI에게 데이터를 넘기기 전에, 우리는 무엇을 해야 하는가?"**

오늘은 그 답을 실제 데이터와 알고리즘으로 배웁니다.

## SECTION 02 · 왜 데이터 정제인가?
**예상 시간: 5:00 ~ 15:00 (10분)**

[스크롤]

AI가 잘못된 데이터를 받으면 **엉뚱한 답을 내놓아요.**

"Garbage In, Garbage Out." 익숙한 말이죠. 데이터를 AI에게 넘기기 전에 오염 여부를 확인하지 않으면 — 이상 감지 알람은 거짓 경보로 가득 차고, 수율 예측 모델의 정확도는 현장에서 쓸 수 없는 수준으로 떨어져요.

[잠깐]

화면에 실제 사례가 있어요. 읽어드릴게요.

"CVD 온도 데이터를 그대로 분석에 썼더니 수율 예측 R²가 0.62였습니다. 결측·이상치·노이즈를 정제하고 나니 동일 모델이 **R² 0.89**로 올라갔습니다. 데이터 정제가 모델 개발보다 수율에 더 직접적인 영향을 줬습니다."

[잠깐]

같은 모델이에요. 코드를 바꾼 게 아니에요. **데이터만 정제했더니 R²가 0.62에서 0.89로 올라간 거예요.** 데이터 정제는 전처리가 아니에요. AI를 현장 도구로 만드는 출발점이에요.

[스크롤]

이제 데이터 오염 3종 카드를 볼게요. 하나씩 설명해드릴게요.

[잠깐]

**첫 번째 — 결측치, Missing Value.**

정의: 센서 고장, 통신 단절, 공정 이벤트로 인해 데이터가 아예 기록되지 않은 구간이에요.

예시 데이터를 보면: Time 10:22 → NaN, 10:23 → NaN, 10:24 → NaN. 3분간 데이터가 통째로 없어요.

이게 왜 문제가 될까요? 현장 영향을 보면 — 반도체에서는 챔버 압력 로그에 2분 공백이 생기면 그 시간 동안 레시피 이탈이 있었는지 판단이 불가해요. 디스플레이에서는 TFT 두께 측정이 누락되면 수율 모델이 왜곡돼요. 2차전지에서는 전해질 온도 NaN이 SoC 계산 오류를 유발해요.

[잠깐]

**두 번째 — 이상치, Outlier.**

정의: 센서 오작동, 전기 잡음, 일시적 공정 이상으로 정상 범위를 크게 벗어난 단일 값이에요.

예시: Temp (°C): 76.2 → 76.8 → **214.5** → 77.1. 앞뒤 값이 76~77°C인데 갑자기 214.5°C가 찍혔어요. 이게 이상치예요. 실제로 공정 온도가 214°C까지 올라간 게 아니라, 센서 전기 잡음이 순간적으로 튄 거예요.

현장 영향: CVD 온도 이상값이 SPC 관리도를 오염시켜서 가짜 OOC 알람이 쏟아져요. 엔지니어들이 알람에 반응하느라 시간을 낭비해요.

[잠깐]

**세 번째 — 노이즈, Sensor Noise.**

정의: 전기 간섭, 센서 민감도, 환경 진동에 의해 정상 신호 위아래로 무작위로 진동하는 잡음이에요.

이상치와의 차이를 짚어드릴게요. 이상치는 정상 범위를 **크게 벗어난** 하나의 값이에요. 노이즈는 정상 범위 **안에서** 위아래로 떨리는 미세한 흔들림이에요.

예시: Target 2.50μm → 실제 측정값: 2.51, 2.49, 2.53, 2.48, 2.52. 평균은 2.50 근처인데 개별 값들이 계속 흔들려요.

현장 영향: 식각 율 노이즈가 종점 판단을 지연시켜요. 광학 두께 진동이 색재현율 검사에서 오판정을 유발해요. 2차전지에서는 전류 노이즈가 충방전 효율 측정 오차를 만들어요.

## SECTION 04 · 정제 알고리즘
**예상 시간: 20:00 ~ 32:00 (12분)**

[스크롤]

**상황에 맞는 알고리즘 선택이 핵심이에요.**

모든 데이터 오염에 통하는 하나의 정제 방법은 없어요. 결측 구간 길이, 데이터 분포, 공정의 물리적 의미에 따라 올바른 방법을 선택해야 해요. 네 가지 알고리즘을 볼게요.

[잠깐]

**첫 번째 — Z-score 이상치 탐지.**

수식이에요: **Z = (x - μ) / σ → |Z| > 3이면 이상치.**

각 데이터 포인트가 평균에서 표준편차의 몇 배나 떨어져 있는지를 계산해요. 3배 이상 떨어지면 이상치로 판정하는 거예요.

아까 214.5°C 예시를 대입해볼게요. 앞뒤 정상 데이터 평균이 77°C, 표준편차가 1.5°C라고 하면 — Z = (214.5 - 77) / 1.5 = 91.7. 이건 명백한 이상치예요.

장점: 계산이 단순하고 해석이 직관적이에요. 정규분포 데이터에서 높은 정확도를 보여요.

주의: 비정규 분포에서는 오판정이 생길 수 있어요. 이상치 자체가 평균과 표준편차를 왜곡한다는 점도 알아두세요.

**추천 적용:** 반도체 CVD 온도, 디스플레이 증착 두께처럼 정규분포에 가까운 공정 파라미터에 가장 잘 맞아요.

[잠깐]

**두 번째 — IQR 방법, 사분범위.**

수식: **IQR = Q3 - Q1. 이상치: x < Q1 - 1.5×IQR 또는 x > Q3 + 1.5×IQR.**

데이터를 작은 것부터 정렬했을 때 하위 25% 지점이 Q1, 상위 25% 지점이 Q3이에요. 그 사이 범위가 IQR이에요. 이 IQR의 1.5배를 벗어나면 이상치로 봐요.

Z-score와의 차이가 핵심이에요. Z-score는 데이터가 정규분포를 따른다고 가정해요. IQR은 분포 가정이 없어요. 비모수적인 방법이에요. 그래서 분포가 이상하거나, 공정 단계마다 분포가 바뀌는 데이터에는 IQR이 더 강건해요.

**추천 적용:** 2차전지 전압·전류처럼 분포가 불규칙하거나 공정 단계별로 분포가 바뀌는 데이터에 맞아요.

[잠깐]

**세 번째 — 이동평균 스무딩.**

수식: **MA(t) = (x[t-n+1] + ... + x[t]) / n. 보통 n = 5~20 사용.**

연속된 n개 값의 평균으로 현재 시점 값을 대체하는 거예요. 윈도우 n이 클수록 더 부드러워지지만 반응 속도가 느려져요.

노이즈 제거에 가장 직관적인 방법이에요. 그리고 이상치 교체에도 써요. 아까 214.5°C를 이동평균(n=5) 값인 77.4°C로 교체한 게 이 방법이에요.

주의: 급격한 공정 변화 구간에서는 실제 신호까지 평활화될 수 있어요. 설비 온도가 레시피 전환으로 빠르게 바뀌는 구간이라면 윈도우를 줄이거나 구간을 분리해서 처리해야 해요.

**추천 적용:** 설비 온도·압력·유량처럼 완만하게 변화하는 연속형 센서 데이터의 노이즈 제거.

[잠깐]

**네 번째 — 선형 보간, 결측치 처리.**

수식: **x(t) = x(t₁) + [x(t₂) - x(t₁)] × (t - t₁) / (t₂ - t₁).**

결측 구간 양쪽의 알려진 값을 직선으로 연결해 빠진 값을 추정하는 거예요. 아까 09:10 NaN이 77.0°C로, 09:15 NaN이 77.2°C로 채워진 게 이 방식이에요. 76.8°C(09:05)와 77.4°C(09:25) 사이를 직선으로 이어서 값을 메운 거예요.

주의: 결측 구간이 길어질수록 실제 공정과 괴리가 커져요. 5분 이내 단기 결측에 적합하고, 5분을 넘으면 도메인 지식 기반의 대체값을 쓰는 게 더 안전해요.

**추천 적용:** 통신 단절로 짧게 누락된 CVD·PVD 공정 파라미터 복원. 5분 이내 결측에 권장.

[스크롤]

알고리즘 선택 3단계 가이드예요. 실제로 어떤 알고리즘을 쓸지 결정할 때 이 순서로 생각하면 돼요.

**Step 1 — 오염 유형은?** 결측 → 보간 / 이상치 → Z-score·IQR / 노이즈 → 이동평균.

**Step 2 — 데이터 분포는?** 정규분포에 가까우면 → Z-score / 분포가 불규칙하거나 왜도가 있으면 → IQR.

**Step 3 — 결측 구간 길이?** 5분 미만이면 → 선형 보간 / 5분 이상이면 → 도메인 기반 대체.

이 세 단계를 순서대로 물어보면 어떤 알고리즘을 써야 하는지가 자연스럽게 나와요.

## SECTION 05 · 정제 워크플로우
**예상 시간: 32:00 ~ 35:00 (3분)**

[스크롤]

**데이터 정제 5단계 프로세스**예요. AI에게 작업을 지시하기 전에 이 흐름을 머릿속에 갖고 있어야 해요.

**1 — 데이터 탐색.** 컬럼별 NaN 비율, 값 분포, 범위를 먼저 확인해요. "데이터가 어떻게 생겼는지"부터 봐야 어떤 오염이 있는지 알 수 있어요.

**2 — 유형 분류.** 결측인지, 이상치인지, 노이즈인지 구분하고 발생 원인을 파악해요. PM 직후에 생긴 결측인지, 전기 잡음 이상치인지, 아니면 센서 노이즈인지에 따라 처리 방법이 달라져요.

**3 — 알고리즘 선택.** 방금 배운 3단계 가이드를 써서 데이터 특성과 공정 맥락에 맞는 방법을 골라요.

**4 — 정제 적용.** 바이브 코딩으로 파이프라인을 자동 구현해요. 이게 오늘 배우는 핵심 스킬이에요.

정제 도구 작업지시서의 **5가지 필수 요소**예요. 이 다섯 가지가 있어야 AI가 현장에서 바로 쓸 수 있는 정제 파이프라인을 만들어줘요.

**① 데이터 설명** — 파일 형식, 컬럼명, 단위, 측정 주기, 기간을 명시해요. AI는 내 데이터가 어떻게 생겼는지 모르거든요.

**④ 산출물 형식** — 정제 전·후 비교 차트, 관리도, 교체 포인트 개수 리포트. 어떤 형태의 결과물이 필요한지 명시해요.

**⑤ 검증 조건** — 정제된 포인트를 별도 마커로 표시하고, 엔지니어가 재확인해야 할 구간을 분리해요. 이게 있어야 AI 결과물을 안전하게 쓸 수 있어요.

[잠깐]

"나는 [공정/설비명]의 [센서명·컬럼·단위·기간] 데이터에서 [결측치 / 이상치 / 노이즈] 문제를 처리하고 싶다. 정제 방법은 [Z-score |Z|>임계값 / IQR 1.5배 / 이동평균 n=윈도우]를 사용하고, 결과물로 [정제 전·후 비교 차트 / 관리도 / 교체 포인트 개수 요약]이 포함된 [HTML 대시보드 / 보고서]를 만들어줘. 정제된 포인트는 별도 마커로 표시하고 엔지니어가 검토해야 할 구간을 분리해줘."
