SECTION 01

Before — 왜 이상 징후를 놓치는가

현장의 현실

설비 센서 로그가 있어요. 온도, 압력, QCM 증착률 데이터가 각각 CSV 파일로 저장돼요. 하루에 1분 단위, 1,440행씩 쌓여요. 설비가 3~4대면 파일이 금방 수십 개가 돼요.

그 파일을 열어보면 — 숫자들이 미세하게 흔들려요. 185.0, 185.2, 185.1, 185.4, 185.3... 엔지니어 입장에서는 "이 정도 흔들림은 그냥 센서 노이즈지" 하고 넘어가기 쉬워요.

이상 징후를 놓치는 4가지 이유

  • 1
    파일이 너무 많아요 — 온도·압력·유량이 각각 따로 저장돼요. 하루에도 수십 개 파일이 쌓여요.
  • 2
    판정 기준이 데이터 안에 없어요 — UCL/LCL을 별도 문서에서 꺼내야 해요.
  • 3
    센서들을 같은 시간축으로 안 봐요 — 각 파일을 따로 열어서 비교하기 어려워요.
  • 4
    전조 신호가 아주 작게 시작돼요 — 한 번 튄 값이 아니라 서서히 올라가는 흐름이라 눈에 안 띄어요.

SECTION 02

이동평균 — 노이즈와 흐름을 구분하는 첫 번째 도구

5-point 이동평균 공식

MA(t) = [x(t) + x(t-1) + x(t-2) + x(t-3) + x(t-4)] / 5

// 창 크기 = 5 (1분 단위 데이터 → 최근 5분 평균)
// 한 번 튄 값: 5분의 1로 희석됨
// 지속 상승 흐름: 이동평균에 그대로 반영됨

AI에게 지시할 때는 반드시 창 크기를 명시하세요.
"이동평균 적용해줘"만으로는 부족해요. 창 크기가 달라지면 OOC 판정 시점도 달라져요.

구분특징이동평균에서의 모습
노이즈 한 번 튀고 바로 정상으로 복귀 이동평균에 거의 영향 없음
드리프트 서서히 한 방향으로 계속 이동 이동평균이 꾸준히 올라감

이동평균은 노이즈와 드리프트를 구분하는 첫 번째 필터예요. 연속 상승 흐름이 보이면 설비 상태가 실제로 변하고 있을 가능성이 커요.

SECTION 03

UCL / LCL / OOC — 정상과 이상의 경계

스펙 ≠ 관리 한계

개념정의설정 주체
제품 스펙 제품 합불 기준 범위 (예: 온도 75~90°C) 고객 / 품질 기준
관리 한계 (UCL/LCL) 정상 운전 시 통계 범위 ±3σ 엔지니어 (정상 이력 기반)

⚠️ 스펙을 넘지 않아도 UCL을 넘으면 이상 신호예요. 우리가 원하는 건 사후 대응이 아니라 사전 감지예요.

관리 한계 계산 공식

Center (CL) = μ // 정상 Lot 20개 기준 평균
UCL = μ + 3σ // 상한 관리 한계
LCL = μ - 3σ // 하한 관리 한계

// Watch: UCL의 85% 라인에 3회 연속 접근
// OOC: UCL 또는 LCL 이탈

Normal / Watch / OOC 3단계

상태정의대응
Normal 이동평균이 UCL/LCL 안에서 안정 계속 모니터링
Watch UCL 85% 라인에 3회 연속 접근 전조 파악, 사전 조치 검토
OOC UCL 또는 LCL을 이탈 현장 즉시 점검, SOP 실행

Watch 단계가 핵심이에요. OOC만 표시하면 이미 늦어요. Watch에서 대응하면 제품 불량 발생 전에 조치할 수 있어요.

SECTION 06

전조 패턴 읽기 + 엔지니어 검증

OOC 발생 전 30분 — 전조 패턴 4가지

📈
연속 상승 — 값이 한 번 튄 게 아니라 5회, 6회 연속 같은 방향으로 움직이면 노이즈가 아닐 가능성이 커요.
〰️
이동평균 기울기 — 원본 값은 흔들려도 이동평균이 꾸준히 올라가면 설비 상태가 실제로 이동하고 있는 거예요.
🔗
여러 센서 동시 변화 — 온도만 아니라 압력도 같은 시간대에 흔들리면 단일 센서 문제가 아닌 설비 조건 변화예요.
↩️
복귀 여부 — 올라갔다 바로 정상으로 돌아오면 일시적 이벤트. 이동평균이 계속 높게 유지되면 주의가 필요해요.
"OOC 발생 시점 기준 30분 전부터 센서별 변화 방향,
이동평균 기울기, 연속 상승 여부, 다른 센서와의
동시 변화를 요약해줘."

엔지니어 검증 체크리스트 5가지

  • 1
    센서 결측 및 타임스탬프 정렬 — 챔버 압력, 소스 온도, QCM 증착률이 같은 Lot ID 기준으로 정확히 동기화됐는지 확인해요.
  • 2
    유기 재료 보트 충진 및 PM 이력 — 재료 교체 직후 오븐 안정화 과정이 OOC로 오진된 건 아닌지 확인해요.
  • 3
    챔버 클리닝 및 진공 펌프 PM — 최근 정비 이력이 압력 Watch 경보와 연관됐는지 파악해요.
  • 4
    QCM 수정진동자 건전성 — 실제 증착률 이상인지, 센서 두께 수명 한계로 인한 측정 감도 왜곡인지 구분해요.
  • 5
    기판 분석 결과 연결 — OOC가 발생한 Lot의 실제 막두께 분석, 휘도 균일성, 양산 수율과 인과관계를 매핑해요.
SECTION 07

실습 프롬프트 템플릿

VTE-03 OLED 증착 설비 이상 감지 프롬프트

OLED 유기물 증착 설비 VTE-03의 1분 주기 센서 로그를 분석해줘. 데이터는 timestamp, equipment_id, lot_id, source_temperature, chamber_pressure, qcm_rate, cooling_water_flow 컬럼이야. 1. lot_id 및 timestamp 기준으로 시계열 정렬하고 결측 데이터와 이상치를 보정해줘. 2. 각 센서에 5-point 이동평균을 적용해줘. 3. 최근 정상 Lot 20개 기준으로 Center(CL), UCL(+3σ), LCL(-3σ)을 계산해줘. 4. 이동평균이 UCL/LCL을 이탈하면 OOC, UCL의 85% 라인에 3회 연속 접근하면 Watch로 표시해줘. 5. "소스 온도 드리프트 → 챔버 압력 상승 → QCM 증착률 요동" 순의 다차원 전조 흐름이 있는지 OOC 발생 전 30분 구간을 역추적해 요약해줘. 결과를 HTML/CSS 기반 실시간 모니터링 대시보드로 만들어줘: 1. VTE 장비별 Normal/Watch/OOC 상태 타일 2. 원본(파란선) + 5-point MA(검은선) + UCL/LCL(빨간 점선) 관리도 3. Lot ID별 OOC 감지 시각 및 센서 경고 알림 카드 4. OOC 발생 전 30분 전조 패턴 요약 5. 현장 정비 SOP 점검 리스트 6. 일일 이상 징후 한 줄 리포트 (아침 인수인계용)

자기 데이터에 맞게 바꿀 3가지

항목템플릿내 현장에 맞게
컬럼명 source_temperature, chamber_pressure, qcm_rate current, vibration, vacuum_level 등
이동평균 창 5-point (= 5분) 데이터 주기에 맞게 (10분, 15분 등)
산출물 형식 HTML 대시보드 Excel 보고서, Slack 알림 등

중요한 건 구조예요. 데이터 → 계산 → 판정 → 산출물 → 검증. 이 구조만 기억하면 어떤 제조 데이터에도 적용할 수 있어요.
