## SECTION 03 · 용어 주석
**예상 시간: 8:00 ~ 11:00 (3분)**

[스크롤]

분석을 시작하기 전에 — **용어부터 고정**해요.

AI에게 공정 데이터를 넘기기 전에 이 용어들을 먼저 설명해줘야 해요. 설명 안 하면 AI는 일반적인 차트만 만들고 공정 의미를 놓쳐요.

화면에 주요 용어 카드들이 있어요. 빠르게 확인할게요.

[잠깐]

**MES** — Manufacturing Execution System. 생산 현장의 Lot, 장비, 공정 조건, 검사 결과를 시간순으로 기록하는 실행 관리 시스템이에요. 오늘 분석할 데이터가 다 여기서 나와요.

**Lot** — 동일 조건으로 함께 처리되는 웨이퍼나 패널 묶음이에요. 분석할 때 추적 단위가 돼요.

**Recipe** — 온도, 압력, 가스 유량, 시간처럼 설비가 따라야 하는 공정 조건 묶음이에요.

**CVD** — Chemical Vapor Deposition. 반응 가스를 기판 표면에서 화학 반응시켜 박막을 형성하는 증착 공정이에요.

그 외에도 **Deposition Thickness** (증착된 박막의 두께, micrometer 단위), **Uniformity** (웨이퍼 안에서 두께가 얼마나 균일한지), **Spec Limit** (공정이 허용하는 상한/하한 기준), **SPC** (통계적 공정 관리)가 있어요.

[잠깐]

이 용어들을 AI에게도 이 수준으로 알려줘야 — 엉뚱한 분석을 줄일 수 있어요. 뒤에서 프롬프트 쓸 때 이 용어들이 그대로 들어가요.

## SECTION 04 · CVD 공정
**예상 시간: 11:00 ~ 19:00 (8분)**

[스크롤]

CVD 공정이 뭔지 간단히 볼게요.

화면에 애니메이션이 있어요. 위에서 반응 가스가 내려오고, 웨이퍼 표면에서 박막이 성장해요. 오른쪽에 두께 게이지가 올라가는 게 보여요. [잠깐]

CVD는 시간 흐름에 따라 데이터가 쌓이는 공정이에요. 7단계예요.

**Load — 기판 투입.** 웨이퍼를 챔버에 넣고 MES에 Lot을 연결해요.

**Pump Down — 진공 형성.** 챔버 내부 압력을 낮춰 반응 환경을 안정화해요.

**Heat — 온도 안정화.** 기판 온도를 Recipe 목표값까지 올리고 안정 시간을 확보해요.

**Gas Flow — 반응 가스 주입.** SiH4, NH3, N2O 같은 반응 가스를 정해진 유량으로 주입해요.

**Deposition — 박막 증착.** 기판 표면에서 화학 반응이 일어나 박막 두께가 시간에 따라 증가해요.

**Purge — 잔류 가스 제거.** 불필요한 반응 가스를 배출하고 챔버를 다음 공정 상태로 전환해요.

**Measure — 두께 측정.** 계측 장비에서 위치별 두께를 측정하고 MES에 저장해요.

[잠깐]

이 7단계 각각에서 데이터가 쌓여요. 온도, 압력, 가스 유량, 증착 시간, 위치별 두께 — 이게 다 MES 데이터가 되는 거예요. 오늘 분석하는 데이터가 바로 이 Measure 단계 결과물이에요.

**예상 시간: 27:00 ~ 30:00 (3분)**

[스크롤]

엑셀로만 이 데이터를 보면 어떤 문제가 있는지 볼게요.

화면에 기존 방식 카드가 있어요.

120개 샘플을 Lot, 장비, Zone별로 필터링하며 평균과 편차를 반복 계산해요. Spec 2.35~2.75 마이크로미터 밖의 데이터를 조건부 서식으로 찾아요. Edge 과두께처럼 위치별 두께 패턴을 눈으로 추적해요. Center/Middle/Edge 위치별 차이를 피벗 테이블과 여러 차트로 따로 확인해요.

그리고 — **보고서용 캡처를 만들 때마다 필터 상태가 바뀌어 재현성이 떨어져요.** 이게 특히 실무에서 골치 아픈 부분이에요.

[잠깐]

그래서 오늘 AI IDE로 이걸 바꿀 거예요.

## SECTION 07 · AI IDE 선택
**예상 시간: 30:00 ~ 40:00 (10분)**

[스크롤]

**"바이브 코딩은 AI IDE에서 일이 됩니다."**

일반 코드 편집기는 "내가 코드를 알고 직접 고치는 도구"에 가까워요. AI IDE는 **현장 문제를 설명하면 코드, 데이터, 화면, 실행 검증까지 함께 진행하는 작업 공간**이에요.

[잠깐]

세 가지 IDE를 비교할게요.

**Cursor** — 코드 파일을 직접 수정하며 AI와 짝 프로그래밍하기 좋아요. 이미 프로젝트 구조가 있고, 컴포넌트나 함수 단위로 빠르게 고칠 때 적합해요.

CVD 실습 지시 예시는 — "src/App.tsx의 CVD 두께 차트에 spec 상한/하한 라인을 추가하고, Edge 이탈 포인트를 강조해줘."

**Antigravity** — 작업 목표를 주면 여러 파일을 탐색하고 계획, 구현, 검증까지 이어가는 에이전트형 IDE예요. 이번 강의처럼 데이터셋, 화면, 분석 로직, 대시보드를 한 번에 만들 때 사용해요.

CVD 실습 지시 예시는 — "CVD 두께 데이터 120개를 만들고, Edge 과두께와 center-edge uniformity를 보여주는 React 대시보드를 구현해줘."

**VS Code + Copilot** — 팀 표준 개발 환경을 유지하면서 반복 코드 작성 속도를 높일 때 적합해요. 회사 보안 정책상 표준 IDE만 써야 할 때 현실적인 선택이에요.

[스크롤]

어떤 상황에서 어떤 IDE를 쓸지 정리한 표예요.

- 파일 하나의 차트 색상이나 문구 바꾸기 → **Cursor**
- 데이터셋·계산 로직·화면·스타일을 한 번에 만들기 → **Antigravity**
- 회사 표준 VS Code 환경 유지 → **VS Code + Copilot**
- 초보 수강생에게 AI가 앱을 만드는 과정 보여주기 → **Antigravity** (Agent 계획, 파일 수정, 터미널 실행, 미리보기 흐름이 강의에 적합)

오늘 실습은 Antigravity로 해요.

## SECTION 08 · Antigravity 사용법
**예상 시간: 40:00 ~ 47:00 (7분)**

[스크롤]

Antigravity 사용법이에요. **설치부터 메뉴 사용까지 화면을 따라가 볼게요.**

화면에 Antigravity IDE 목업 창이 있어요. 9단계예요.

[잠깐]

**1단계 — 설치 파일 받기.** 공식 배포 페이지에서 운영체제에 맞는 설치 파일을 내려받고 실행해요. 회사 PC라면 보안 정책상 설치 권한, 프록시, GitHub 접속 가능 여부를 먼저 확인해야 해요.

**2단계 — 로그인과 기본 설정.** 계정 로그인 후 모델, 테마, 터미널 기본 shell, Git 연동 상태를 확인해요.

**3단계 — 프로젝트 폴더 열기.** 좌측 Explorer에서 lecture03 폴더를 열어 src, public, package.json 구조를 확인해요. App.tsx는 화면, index.css는 디자인, package.json은 실행 명령이에요.

**4단계 — 데이터와 요구사항 붙이기.** CVD 두께 데이터 컬럼, spec 기준, MES 용어 설명을 Agent에게 먼저 제공해요. [잠깐] **이 단계가 빠지면 AI는 일반적인 차트만 만들고 공정 의미를 놓쳐요.** 가장 중요한 단계예요.

**5단계 — Agent에게 목표 말하기.** 오른쪽 채팅 패널에 "CVD 두께 데이터를 분석하는 대시보드 웹앱을 만들어줘"라고 말하되, 결과물 형식과 검증 조건까지 함께 적어요.

**6단계 — 계획 확인 후 승인.** AI가 제안한 작업 계획에서 데이터 생성, 요약 지표, 시각화, 반응형 화면, 빌드 검증이 포함됐는지 확인해요. 빠진 항목은 구현 전에 바로 추가 지시해요.

**7단계 — 실행과 검증.** 터미널에서 npm install, npm run dev, npm run build를 실행하고 오류를 AI에게 다시 전달해요. **오류 메시지는 요약하지 말고 원문 그대로 붙이는 편이 좋아요.**

**8단계 — 화면 확인 후 수정 지시.** 미리보기 화면에서 글자 겹침, 차트 의미, 공정 용어 설명을 확인해요. "보기 좋게"보다 **"Edge 과두께가 더 선명하게 보이게"**처럼 구체적으로 말해요.

**9단계 — 커밋과 배포.** 완성 후 git status로 변경 파일을 확인하고, 커밋 메시지를 작성한 뒤 GitHub Pages에 배포해요.

[스크롤]

화면에 메뉴별 역할 표가 있어요.

- **Explorer** — 파일 구조 확인. App.tsx, index.css, package.json을 찾아요.
- **Agent / Chat** — 작업 목표 입력. CVD 데이터셋 생성, MES 용어 주석, 대시보드 요구사항을 한 번에 전달해요.
- **Editor** — 코드 확인. AI가 만든 thicknessData, 대시보드 컴포넌트가 실제로 들어갔는지 확인해요.
- **Terminal** — 실행 검증. npm run dev로 화면을 띄우고 npm run build로 배포 가능한지 확인해요.
- **Preview** — 사용자 화면 점검. 섹션 간격, 애니메이션, 모바일 줄바꿈, 툴팁 위치를 확인해요.
- **Source Control** — 변경 이력 관리. 수정 파일을 확인하고 의미 있는 메시지로 커밋해요.

## SECTION 09 · 바이브 코딩 프롬프트
